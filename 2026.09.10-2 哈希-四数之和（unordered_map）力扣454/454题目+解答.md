# LeetCode 454 四数相加 II

日期：2026.09.10

## 题目描述

给你四个整数数组 nums1、nums2、nums3 和 nums4 ，数组长度都是 n ，请你计算有多少个元组 (i, j, k, l) 能满足：
$$0 \le i, j, k, l \lt n$$
$$nums1[i] + nums2[j] + nums3[k] + nums4[l] = 0$$

**示例 1：**
输入：nums1 = [1,2], nums2 = [-2,-1], nums3 = [-1,2], nums4 = [0,2]
输出：2
解释：
两个元组如下：

1. (0, 0, 0, 1) -> nums1[0] + nums2[0] + nums3[0] + nums4[1] = 1 + (-2) + (-1) + 2 = 0
2. (1, 1, 0, 0) -> nums1[1] + nums2[1] + nums3[0] + nums4[0] = 2 + (-1) + (-1) + 0 = 0

**示例 2：**
输入：nums1 = [0], nums2 = [0], nums3 = [0], nums4 = [0]
输出：1

**提示：**

- n == nums1.length
- n == nums2.length
- n == nums3.length
- n == nums4.length
- $1 \le n \le 200$
- $-2^{28} \le nums1[i], nums2[i], nums3[i], nums4[i] \le 2^{28}$

## ✅ AC最终代码（版本一 哈希表 $O(n^2)$）

```cpp
//2026.9.10
//版本一：基础哈希分组解法
class Solution {
public:
    //思路：分为nums1+nums2=s和nums3+nums4=t,用哈希表记录有多少对下标对应元素的和为同一个s，即key：s，value：个数。再遍历此哈希表，寻找-t对应的value，找到了则答案+value
    int fourSumCount(vector<int>& nums1, vector<int>& nums2, vector<int>& nums3, vector<int>& nums4) {
        int n = nums1.size();
        unordered_map <int, int> mp;
        int ans = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                int s = nums1[i] + nums2[j];
                mp[s]++;
            }
        }
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                int t = nums3[i] + nums4[j];
                if (mp.find(-t) != mp.end()) {
                    ans += mp[-t];
                }
            }
        }
        return ans;
    }
};
```

## 🧪 暴力解法（四层循环 $O(n^4)$，会超时）

```cpp
/*暴力解法，\(n=200\)时运算量巨大，无法通过*/
class Solution {
public:
    int fourSumCount(vector<int>& nums1, vector<int>& nums2, vector<int>& nums3, vector<int>& nums4) {
        int n = nums1.size();
        int ans = 0;
        for(int i = 0; i < n; i++){
            for(int j = 0; j < n; j++){
                for(int k = 0; k < n; k++){
                    for(int l = 0; l < n; l++){
                        if(nums1[i]+nums2[j]+nums3[k]+nums4[l]==0){
                            ans++;
                        }
                    }
                }
            }
        }
        return ans;
    }
};
```

## 🧠 思路推导

1. 暴力思路：四层循环枚举全部四元组，判断四数之和是否等于0。
   - 缺点：时间复杂度 $O(n^4)$，$(n=200)$ 时计算量达到 $200^4=16$ 亿次，严重超时。
2. 哈希分组优化思路：
   - 原等式：$(nums1[i] + nums2[j] + nums3[k] + nums4[l] = 0)$
   - 等式变形：$\boldsymbol{nums1[i] + nums2[j] = -(nums3[k] + nums4[l])}$
   - 令 $s = nums1[i]+nums2[j]$，$t = nums3[k]+nums4[l]$，等价于找满足 $s=-t$ 的配对组合。
   - 使用`unordered_map`：**key存前两个数组两数之和s，value存该和出现的组合次数**。
   - 第一步双层循环：遍历 nums1、nums2，统计所有两数之和以及出现次数存入哈希表。
   - 第二步双层循环：遍历 nums3、nums4，计算每一组的和 t；去哈希表查找 `-t`：
     - 如果存在key `-t`：代表有 `mp[-t]` 种 (i,j) 组合可以和当前(k,l)配对，把次数累加到答案。
     - 如果不存在，直接跳过，累加0。

> 
> ⚠️关键细节：本题**不需要存储下标**，只统计组合数量。不同下标只要求和结果一样，就可以互相配对，直接次数相乘累加。

### 拓展：meet‑in‑the‑middle（折半枚举思想）

本题的2+2分组就是经典的**折半枚举(meet‑in‑the‑middle)** 算法。

- 核心思想：把原本需要暴力枚举的 $m$ 组，对半切分成前后两部分；先枚举前半部分全部可能结果保存，再枚举后半部分，在保存的结果中做匹配查找。
- 对于本题4个数组：暴力复杂度 $O(n^4)$，对半拆为2+2后复杂度降为 $O(n^2)$，指数减半。

> 
> 思考问题：如果数组数量继续增加，例如 6 个数组拆成 3+3，复杂度会如何变化？
> 
> 
> - $m$ 为数组总个数，对半拆分后，每一组包含 $\dfrac{m}{2}$ 个数组；
> - 时间复杂度为 $O(n^{\frac{m}{2}})$。
> - 6数组拆3+3：复杂度 $O(n^3)$；8数组拆4+4：$O(n^4)$。

可以看到：**折半枚举只能把暴力的指数减半，并不能消除指数。数组数量越多，时间开销依旧会快速上涨。**

- 4数组场景：$O(n^2)$，效果极佳；
- 6数组场景：相比原始暴力 $O(n^6)$ 依旧巨大提升，但 $n$ 稍大就会超时；
- 适合场景：**数组/集合数量不大，单组数据规模 n 适中**。

> 
> 区分两道高频易混题目：
> 
> 
> 1. LeetCode 454 四数相加 II：4个独立数组，元素取自不同数组 → 使用折半枚举2+2哈希。
> 2. LeetCode 18 四数之和：**同一个数组内选4个元素**，不能重复选取下标 → 不可直接使用该分组哈希，采用排序+双指针。

## 📊 复杂度分析

- 暴力解法
  - 时间复杂度：$O(n^4)$，四层循环
  - 空间复杂度：$(O(1))$，仅使用常数额外空间
- 版本一 / 版本二哈希分组解法
  - 时间复杂度：$O(n^2)$，两组双层循环，哈希查找平均 $(O(1))$
  - 空间复杂度：$O(n^2)$，最坏情况哈希表存储 $n^2$ 种不同的两数之和

## 💡学到的知识点

1. **分组降阶（折半枚举 meet‑in‑the‑middle）**：把 $m$ 重循环拆成两半，将 $O(n^m)$ 降低到 $O(n^{m/2})$；本题m=4，拆2+2得到$O(n^2)$，也是本题时间复杂度的理论下界，不存在时间复杂度更低的算法。
2. `unordered_map` key保存求和值，value保存**组合计数**，不是下标；和两数之和题目用途区分开。
3. 等式变形 $a+b+c+d=0 \Rightarrow a+b = -(c+d)$，求和转化为哈希查找。
4. 注意：题目允许不同数组取相同下标，没有不能复用元素的限制。

## ✨拓展思考（工程层面优化，不改变时间复杂度大O）

1. `unordered_map`存在哈希冲突，可调用`mp.reserve(n*n)`预分配桶，减少rehash带来的时间损耗。
2. 备选方案：将前半部分全部和存入vector排序，后半部分用二分查找统计数量；规避哈希冲突，但引入 $O(n^2 \log n)$ 的对数因子。
3. 溢出风险：题目元素范围 $-2^{28}\sim 2^{28}$，两数相加存在超出int安全范围的风险；若测试用例数值放大，需要将和的变量改为`long long`，map的key同步更换为`long long`。
4. 分组可以交换，例如 nums1+nums3 与 nums2+nums4，对结果正确性无影响。
